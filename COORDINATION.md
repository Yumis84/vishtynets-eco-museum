# Координация параллельной работы

Статус: ACTIVE
Дата: 2026-09-02

## Цель

Дима и другие агенты могут работать параллельно над новым сайтом, но не должны дублировать работу, перетирать изменения друг друга или выполнять одну и ту же задачу независимо.

Главный принцип: **одна общая очередь задач, один реестр миграции, отдельные ветки, Pull Request перед слиянием в `main`.**

## Этапы

1. **Инвентаризация** — найти и описать материалы старого сайта.
2. **Назначение** — закрепить конкретный материал/участок за исполнителем.
3. **Работа** — исполнитель работает только в своей ветке.
4. **PR** — результат оформляется отдельным Pull Request.
5. **Проверка** — другой участник проверяет результат и отсутствие дублей/конфликтов.
6. **Слияние** — только после проверки результат попадает в `main`.
7. **Верификация** — проверяется соответствие старому источнику и полнота миграции.

## Распределение ответственности

### Дима

Основной разработчик нового сайта:

- архитектура и код;
- шаблоны и интерфейс;
- техническая интеграция контента;
- исправление функционала;
- технические миграционные задачи.

### Миграционный агент / контентный исполнитель

- аудит `wystynez.ru`;
- поиск страниц, изображений и документов;
- сопоставление старый материал → новое место;
- source-preserving перенос текстов и исторических материалов;
- фиксация URL, дат, подписей и photo credits;
- контроль полноты и дублей;
- ведение `MIGRATION_INVENTORY.md`.

## Правила против дублей

- Перед началом любой работы сначала проверить `MIGRATION_INVENTORY.md` и открытые PR/ветки.
- Если материал уже имеет статус `IN PROGRESS`, второй исполнитель его не изменяет без согласования.
- Если материал уже `MIGRATED` или `VERIFIED`, не создавать альтернативную копию.
- Если два изменения затрагивают один файл, работу необходимо согласовать до записи.
- Не переписывать исторический материал литературно во время миграции.
- Не удалять старый материал только потому, что он кажется устаревшим.

## Правила веток

- `main` — интеграционная ветка.
- Для каждой самостоятельной задачи используется отдельная ветка.
- Прямые изменения `main` не используются для рабочих задач.
- PR должен содержать краткое описание: что сделано, какие legacy URL обработаны, какие файлы изменены, что осталось.

## Правило источника

Для каждого мигрированного материала сохраняются:

- исходный legacy URL;
- название;
- дата/период;
- изображения;
- подписи и photo credits;
- документы и ссылки;
- статус миграции.

Старый `wystynez.ru` остаётся архивным источником. Новые контакты, цены, режим работы и другие оперативные данные публикуются как текущие только после отдельной проверки.

## Главный реестр

`MIGRATION_INVENTORY.md` является общей картой миграции. При обнаружении нового материала его сначала добавляют в реестр, а затем назначают исполнителя.

Если подходящей записи ещё нет — создаётся одна запись. Не создаются параллельные записи одного материала.
